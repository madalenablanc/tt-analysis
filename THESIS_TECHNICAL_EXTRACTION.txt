--------------------------------------------------------------------------------
1. FULL ANALYSIS WORKFLOW
--------------------------------------------------------------------------------

The pipeline has two main phases followed by a BDT training and statistical
interpretation stage.

  NanoAOD (EOS/XRootD)
      |
      v  fase0_data_mutau.py / fase0_dy.py / fase0_ttjets.py / fase0_qcd_data.py
  Phase 0: Lightweight skimming — trigger filter, lumi mask, define observables,
           snapshot proton collections. Output: skimmed flat ROOT trees on EOS.
      |
      v  fase1_data.py / fase1_dy.py / fase1_ttjets.py / fase1_qcd.py
  Phase 1: Full event selection — object ID, pT, eta, DeltaR, charge.
           Compute scale factors. Output: selected trees with weight branches.
      |
      v  merge_pp_mutau.py
  Merging + Proton Mixing — merge files, mix pileup protons (0.245 weight),
  produce merged ROOT files on EOS.
      |
      v  sinal.cpp
  Signal Processor — read MC ntuple (ntp1), apply signal selection, apply
  fiducial proton cuts per era, apply radiation damage weights, compute xi
  up/down systematics, write MuTau_sinal_SM_2018_july.root.
      |
      v  TMVAClassification.C
  TMVA BDT Training — reads background_total-protons_syst.root +
  MuTau_sinal_SM_2018_july.root, trains BDT, writes
  dataset/weights/TMVAClassification_BDT.weights.xml.
      |
      v  TMVAClassificationApplication.C
  BDT Application — applies trained BDT to data/DY/QCD/TTJets/signal,
  writes TMVApp_{data,DY,QCD,ttjets,sinal}.root.
      |
      v  save_shapes.cpp
  Shapes Production — reads merged ROOT files + TMVApp files, fills 1D
  histograms for all observables and BDT output, applies DY_SCALE,
  writes MuTau_shapes.root.
      |
      v  datacards/mutau_bdt_shape.txt  -->  CMS Combine
  Statistical Interpretation — text2workspace, combine asymptotic CLs limits,
  signal strength r = sigma / sigma_SM.


Key output files on EOS:
  /eos/user/m/mblancco/samples_2018_mutau/Data_2018_UL_MuTau_nano_merged_proton_vars.root
  /eos/user/m/mblancco/samples_2018_mutau/DY_2018_UL_MuTau_nano_merged_pileup_protons.root
  /eos/user/m/mblancco/samples_2018_mutau/ttjets_2018_UL_MuTau_nano_merged_pileup_protons.root
  /eos/user/m/mblancco/samples_2018_mutau/QCD_2018_UL_MuTau_nano_merged_proton_vars_new.root
  MuTau_sinal_SM_2018_july.root          (signal, local)
  MuTau_shapes.root                      (final shapes for Combine, local)

2. EVENT SELECTION (mu tau_h channel)
--------------------------------------------------------------------------------

All cuts confirmed from:
  - fase0_data_mutau.py  (phase 0 filter)
  - fase1_data.py / fase1_dy.py / fase1_ttjets.py  (phase 1 filter)


TRIGGER
  HLT_IsoMu24 == 1   (single isolated muon trigger, 2018)
  Applied at phase 0 in fase0_data_mutau.py line 229.


LUMI MASK
  A certified luminosity list (dadosluminosidade.txt) is loaded into a C++ map
  and applied as lumi_filter(run, luminosityBlock) during phase 0 skimming.
  Implemented in fase0_data_mutau.py lines 152-191.


MUON SELECTION
  Cut            Value               Branch / condition in phase 1
  --------------------------------------------------------
  MVA ID         >= 3 (Tight)        muon_id > 3
  pT             > 35 GeV            muon_pt > 35.
  |eta|          < 2.4               fabs(muon_eta) < 2.4

  NanoAOD source: Muon_mvaId[0], Muon_pt[0], Muon_eta[0]


TAU (hadronic) SELECTION
  All tau ID discriminants from DeepTau 2017 v2p1.

  Cut        NanoAOD variable                  Threshold   Working point
  -------------------------------------------------------------------
  VSjet      Tau_idDeepTau2017v2p1VSjet[0]     > 63        >= VeryTight (bit 6)
  VSe        Tau_idDeepTau2017v2p1VSe[0]       > 7         >= Tight (bit 3)
  VSmu       Tau_idDeepTau2017v2p1VSmu[0]      > 1         >= Loose (bit 1)
  pT         Tau_pt[0]                          > 100 GeV
  |eta|      Tau_eta[0]                         < 2.4


PAIR-LEVEL CUTS
  Opposite charge:    muon_charge * tau_charge < 0
  DeltaR separation:  tau.DeltaR(muon) > 0.4  (TLorentzVector)


JET AND B-TAG
  Saved at phase 0 for later use. b-tagging uses DeepCSV:
    n_b_jet = count of jets with Jet_btagDeepB > 0.4506
  No explicit b-jet veto is applied in phase 1 selection filters, but n_b_jet
  is available as a variable for further cuts if needed.


MET
  MET_pt and MET_phi stored from NanoAOD in phase 0.
  Used as BDT input variable. No explicit MET cut in event selection.

3. PROTON SELECTION AND PPS
--------------------------------------------------------------------------------

Signal selection is implemented in sinal.cpp.
For data/MC backgrounds, only one-proton-per-arm requirement is applied.


ONE PROTON PER ARM REQUIREMENT

  Data and QCD (real multiRP protons from NanoAOD):
    Scan arm vector, take first proton on each arm:
      for j in proton_multi_arm: if arm==0 -> xi1; if arm==1 -> xi2
    Require both arms: xi1 > 0 && xi2 > 0

  MC (DY, ttbar) pileup protons (mixed from proton pool):
    xi_arm1_1 >= 0 && xi_arm2_1 >= 0

  Signal (from MC ntuple ntp1):
    if (xi->size() != 2) continue;   // exactly one proton per arm


UPPER XI FIDUCIAL CUT (thetaX limit)
  Applied in sinal.cpp via crossing-angle-dependent TF1 functions:

    TF1 limit_fun_arm_0("limit_fun_arm_0",
      "-(8.44219E-07*[xangle]-0.000100957)+"
      "(([xi]<(0.000247185*[xangle]+0.101599))*-(1.40289E-05*[xangle]-0.00727237)"
      "+([xi]>=(0.000247185*[xangle]+0.101599))*-(0.000107811*[xangle]-0.0261867))"
      "*([xi]-(0.000247185*[xangle]+0.101599))", 0, 1);

    TF1 limit_fun_arm_1("limit_fun_arm_1",
      "-(-4.74758E-07*[xangle]+3.0881E-05)+"
      "(([xi]<(0.000727859*[xangle]+0.0722653))*-(2.43968E-05*[xangle]-0.0085461)"
      "+([xi]>=(0.000727859*[xangle]+0.0722653))*-(7.19216E-05*[xangle]-0.0148267))"
      "*([xi]-(0.000727859*[xangle]+0.0722653))", 0, 1);

    // Reject event if thetaX exceeds limit:
    if((*thx)[0] > -limit_fun_arm_0.Eval(0.5) ||
       (*thx)[1] > -limit_fun_arm_1.Eval(0.5)) continue;

  The crossing angle (xangle) is determined from the event's fractional index
  within the sample, mapping to 2018 fill periods (130-160 urad):
    fraction <= 0.134  -> xangle = 130
    fraction in (0.134, 0.149) -> 131
    ...
    fraction >= 0.925  -> 160

RADIATION DAMAGE CORRECTIONS
  Applied per era using 2D histograms from two ROOT files:
    pixelEfficiencies_multiRP_reMiniAOD.root
    pixelEfficiencies_radiation_reMiniAOD.root

  Example (Era A):
    TH2F *raddamage56_match = file_multi.Get("Pixel/2018/2018A/h56_220_2018A_all_2D");
    TH2F *raddamage56       = file_rad.Get("Pixel/2018/2018A/h56_210_2018A_all_2D");
    weight *= raddamage56->GetBinContent(raddamage56->FindBin(trackx1[arm56], tracky1[arm56]));
    weight *= raddamage56_match->GetBinContent(...);
    // Same for arm 45 (h45_... histograms)

  The product of four 2D efficiency values (near + far) x (arm 45 + arm 56)
  is applied as a multiplicative per-event weight.
  Same era-based logic applies for B1, B2, C, D1, D2.


XI SYSTEMATIC VARIATIONS (up/down)
  Loaded from reco_charactersitics_version1.root:
    TGraphErrors* xi_sist_1 =
      proton_sist_1.Get("2018_TS1_TS2/multi rp-0/xi/g_systematics_vs_xi");
    TF1 xi_sist_inter_1("xi_sist_inter_1", "pol20", 0, 10);
    xi_sist_1->Fit("xi_sist_inter_1");
    // Same for arm 1

  Up/down xi stored as output branches:
    xi_arm1_1_up = xi_arm1 + xi_sist_inter_1.Eval(xi_arm1)
    xi_arm1_1_dw = xi_arm1 - xi_sist_inter_1.Eval(xi_arm1)
    xi_arm2_1_up = xi_arm2 + xi_sist_inter_2.Eval(xi_arm2)
    xi_arm2_1_dw = xi_arm2 - xi_sist_inter_2.Eval(xi_arm2)


PROTON POOL (pileup proton mixing for backgrounds)
  Script: proton_pool_MuGamma.cpp

  Proton pool extracted from QCD data (same HLT_IsoMu24 trigger), saving
  multiRP proton kinematics (xi, arm, thetaX, thetaY) to separate ROOT files:
    /eos/cms/store/group/phys_smp/Exclusive_DiTau/proton_pool_2018/
        proton_pool_MUGAMMA_2018_UL_fromQCD_nano_{N}.root

  These are mixed with DY/ttbar MC events by merge_pp_mutau.py to simulate
  the expected pileup proton background rate.

  Probability that random pileup provides protons on both arms: 0.245

  Sample    N events          Sum(gen_weights)
  ---------------------------------------------------

  ttbar     304,895,029       6.108 x 10^11

  Script: check_mc_normalization.py
  Accesses: Runs tree, branch genEventSumw (+ genEventCount)


MC SCALE FACTORS
  Scale = (L x sigma) / Sum(gen_weights)

  DY_SCALE   = (54900 x 6077.22) / 3.323e12  = 1.004e-4
  TTBAR_SCALE = 1.0  (see ttbar normalization below)


NORMALIZATION PIPELINE

  DY:
    event_weight (fase1_dy.py)  = generator_weight x mu_trig_sf x mu_idiso_sf x mu_reco_sf
    weight (merge)              = event_weight x 0.245
    final_weight (plotting)     = weight x DY_SCALE
                                = gen_w x SFs x 0.245 x 1.004e-4
                                ~ 17000 x 0.97 x 0.245 x 1.004e-4  ~  0.4 per event

  ttbar:
    event_weight (fase1_ttjets.py) = 0.15 x mu_trig_sf x mu_idiso_sf x mu_reco_sf
    weight (merge)                 = event_weight x 0.245
    final_weight (plotting)        = weight x 1.0   (TTBAR_SCALE = 1.0)

    The hardcoded 0.15 factor:
      L x sigma / Sum(gen_w) x avg_gen_w = 7.476e-5 x 2000 = 0.1495 ~ 0.15
      Verified to 0.3% in validate_normalization.py.

  Signal (gamma-gamma -> tau-tau):
    weight_sample = 54900 x weight_sm[0] / (4000 x 1000)
    final_weight  = weight_sample x radiation_damage_weight x muon_SFs

  QCD:
    Data-driven. No MC normalization. weight = 1.0.


PROTON ACCEPTANCE FACTOR: 0.245
  Probability of having pileup protons reconstructed on both PPS arms
  simultaneously. Applied as multiplicative weight during merge step to
  DY and ttbar backgrounds.


EXPECTED YIELDS AFTER PROTON CUT
  Sample    Raw events    Weighted yield
  --------------------------------------
  DY        1,704         486 events
  ttbar     26,649        954 events


NORMALIZATION FORMULA (summary)
  weight = (L x sigma / Sum_w_gen) x generator_weight x SF_muon x eff_proton

  Where:
    L            = 54,900 pb^-1
    sigma        = production cross-section (pb)
    Sum_w_gen    = sum of generator weights from original NanoAOD Runs tree
    generator_weight = per-event generator weight (from aMC@NLO)
    SF_muon      = trigger x ID/Iso x reconstruction scale factors
    eff_proton   = 0.245

6. OBSERVABLES AND FEATURE ENGINEERING
--------------------------------------------------------------------------------

All defined in phase 0 (fase0_data_mutau.py) and used in BDT training and
plotting. All use TLorentzVector arithmetic.

  Variable          Formula / Definition
  -----------------------------------------------------------------------
  sist_mass         M(mu + tau) = (muon + tau).M()
  sist_pt           pT(mu + tau) = (muon + tau).Pt()
  sist_rap          Y(mu + tau) = (muon + tau).Rapidity()
  acop              1 - |Delta_phi| / pi
                    Delta_phi = |phi_mu - phi_tau|;
                    if Delta_phi > pi: Delta_phi = 2*pi - Delta_phi;
                    acop = |Delta_phi| / pi
  met_pt            MET_pt (missing transverse energy)
  delta_r           DeltaR(mu, tau) = tau.DeltaR(muon)  [TLorentzVector]
  xi_arm1_1         xi of leading multiRP proton with arm == 0
  xi_arm2_1         xi of leading multiRP proton with arm == 1
  Rapidity matching Y_sys - 0.5 * log(xi1/xi2)
  Mass matching     sist_mass - 13000 * sqrt(xi1 * xi2)
  Proton inv. mass  M_pp = 13000 * sqrt(xi1 * xi2)  [sqrt(s) = 13000 GeV]


PHYSICAL MOTIVATION:

  Acoplanarity:
    For exclusive production gamma-gamma -> tau tau, the two-body final state
    is back-to-back in the transverse plane (Delta_phi = pi), giving acop ~ 0.
    Backgrounds (DY, QCD, ttbar) fill the full acop range up to 1.

  Rapidity matching:
    For a central exclusive process gamma-gamma -> tau tau, the rapidity of
    the central system equals 0.5 * log(xi1/xi2). The residual
    Y_sys - 0.5*log(xi1/xi2) peaks at 0 for signal but is flat for
    backgrounds where the protons are not kinematically correlated with
    the tau pair.

  Mass matching:
    Similarly, M_sys - sqrt(s * xi1 * xi2) peaks near 0 for signal.
    For unrelated pileup protons, this quantity is broadly distributed
    and typically strongly negative.

TMVA BDT TRAINING  (TMVAClassification.C)

  Input files:
    Signal:     MuTau_sinal_SM_2018_july.root  (tree "tree")
    Background: background_total-protons_syst.root  (tree "tree")

  Training configuration:
    nTrain_Signal     = 6500
    nTrain_Background = 15000
    SplitMode         = Random
    NormMode          = NumEvents

  Signal weight expression:
    weight * weights_bsm_sf[51]
    (index 51 = SM point in BSM reweighting vector)

  Background weight expression:
    weight

  Global tree-level weights:
    signalWeight = backgroundWeight = 1.0
    (all normalization handled by per-event weight expressions above)

  INPUT VARIABLES (9 total):
    1.  sist_rap                              central system rapidity
    2.  acop                                  acoplanarity
    3.  sist_pt                               total pT  [GeV]
    4.  mu_pt                                 muon pT  [GeV]
    5.  tau_pt                                tau pT   [GeV]
    6.  sist_mass                             invariant mass  [GeV]
    7.  sist_mass - sqrt(13000^2 * xi1*xi2)   invariant mass matching  [GeV]
    8.  met_pt                                MET  [GeV]
    9.  sist_rap - 0.5*log(xi1/xi2)           rapidity matching

    Note: xi1, xi2 are tree aliases for xi_arm1_1, xi_arm2_1 to avoid TMVA
    parser misreading array indexing notation.

8. COMPUTATIONAL OPTIMIZATION
--------------------------------------------------------------------------------

ROOT EnableImplicitMT
  All phase 0 and phase 1 scripts call ROOT.EnableImplicitMT() at startup.
  This activates implicit multithreading for RDataFrame::Snapshot, parallelizing
  the event loop across all available CPU cores.

MT FALLBACK (fase0_data_mutau.py)
  Phase 0 data skimmer includes automatic fallback to single-thread mode:
    def try_rdf(input_spec, use_mt=True):
        if use_mt: ROOT.EnableImplicitMT()
        else:       ROOT.DisableImplicitMT()
        df = ROOT.RDataFrame("Events", input_spec)
        df_defs = build_df_defs(df)
        df_defs.Snapshot("tree", part_file, COLUMNS)
  Tries MT first; falls back to ST if failure occurs.

RDataFrame USAGE
  Entire phase 0 and phase 1 processing uses ROOT.RDataFrame instead of
  manual TTree loops. Benefits:
    - Lazy evaluation (filter/define nodes compiled JIT before execution)
    - Implicit parallelism with MT enabled
    - Efficient multi-file chaining

SUBPROCESS ISOLATION (fase0_data_mutau.py)
  Each file processed as an independent subprocess, isolating potential
  segfaults/memory issues from the driver process:
    def run_worker(single_idx):
        return subprocess.run(
            [sys.executable, sys.argv[0], "--single-index", str(single_idx)], ...)

RESUME CAPABILITY
  All phase 0/1 scripts maintain a JSON resume file tracking completed file
  indices, enabling restart after interruption without reprocessing:
    .mutau_phase0_resume.json
    .mutau_phase1_dy_resume.json
    .mutau_phase1_ttjets_resume.json
    .mutau_phase1_qcd_resume.json

XROOTD RESILIENCE (fase0_data_mutau.py)
  Tries multiple redirectors in order:
    root://cms-xrd-global.cern.ch
    root://xrootd-cms.infn.it
  Auto-renews VOMS proxy if expiring (voms-proxy-init -voms cms -valid 24:00).
  Falls back to local xrdcp caching on failure.
